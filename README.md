# AWS Terraform Bootstrap Service

## Overview

This project provisions AWS infrastructure required for Terraform remote state management using Amazon S3.

It provides a centralized and secure S3 backend for storing Terraform state files across multiple projects and environments.

## Features

- Amazon S3 bucket for Terraform remote state storage.
- S3 bucket versioning enabled.
- Server-side encryption using AES-256 (SSE-S3).
- S3 public access blocked.
- HTTPS-only bucket access enforced.
- Native S3 state locking using lockfiles.
- AWS Systems Manager Parameter Store integration.
- Protection against accidental S3 bucket deletion.
- Terraform outputs for resource information.

## AWS Credentials Configuration

This project uses AWS CLI named profiles for authentication.

### 1. Configure AWS Credentials

File: `~/.aws/credentials`

```ini
[sk-mycloud]
aws_access_key_id = YOUR_ACCESS_KEY
aws_secret_access_key = YOUR_SECRET_KEY
```

### 2. Configure AWS Profile(Optional)

File: `~/.aws/config`

```ini
[profile sk-mycloud]
region = ap-south-1
output = json
```

### 3. Set AWS Profile

```bash
export AWS_PROFILE=sk-mycloud
export AWS_REGION=ap-south-1
```

### 4. Verify AWS Authentication

```bash
aws sts get-caller-identity
```

Ensure the correct AWS account and IAM identity are returned.

## S3 Remote Backend Configuration

The bootstrap project initially uses local Terraform state because the S3 bucket must be created before it can be used as a remote backend.

After successfully provisioning the S3 bucket, retrieve its name:

```bash
terraform output -raw s3_state_bucket
```

### Configure S3 Backend

Add the following backend configuration to the bootstrap Terraform project.

Replace the bucket name with the actual bucket name generated by Terraform.

```hcl
terraform {
  backend "s3" {
    bucket       = "YOUR_CREATED_S3_BUCKET"
    key          = "bootstrap/terraform.tfstate"
    region       = "ap-south-1"
    encrypt      = true
    use_lockfile = true
  }
}
```

### Migrate Local State to S3

Execute:

```bash
terraform init -migrate-state
```

Confirm the migration when prompted.

Terraform will migrate the existing local state into the S3 backend.

**Note:** Keep a secure backup of the local state until migration is successfully verified.

## Using the Backend in Other Terraform Projects

The centralized S3 bucket can be reused by multiple Terraform projects and environments.

Use a unique state key for each project or environment.

Example backend configuration for a development environment:

```hcl
terraform {
  backend "s3" {
    bucket       = "YOUR_CREATED_S3_BUCKET"
    key          = "dev/terraform.tfstate"
    region       = "ap-south-1"
    encrypt      = true
    use_lockfile = true
  }
}
```

Initialize the project:

```bash
terraform init
```

Example state file organization:

| Environment | S3 State Key |
|---|---|
| Bootstrap | `bootstrap/terraform.tfstate` |
| Development | `dev/terraform.tfstate` |
| QA | `qa/terraform.tfstate` |
| Staging | `staging/terraform.tfstate` |
| Production | `prod/terraform.tfstate` |

## Cleanup and Resource Destruction

**Warning:** Do not destroy a shared backend bucket while other Terraform projects depend on it.

### 1. Back Up Remote State

From the bootstrap Terraform directory:

```bash
terraform state pull > bootstrap-state-backup.tfstate
```

Store the backup securely outside the Git repository.

### 2. Migrate Remote State Back to Local

Temporarily remove the S3 backend block from the Terraform configuration.

Execute:

```bash
terraform init -migrate-state
```

Confirm migration to local state.

Verify:

```bash
terraform state list
terraform output
```

### 3. Empty the S3 Bucket

Since S3 versioning is enabled, deleting current objects is not sufficient.

Delete all object versions and delete markers before destroying the bucket.

You can perform this operation through the AWS Console:

1. Open Amazon S3.
2. Select the Terraform state bucket.
3. Open the Objects tab.
4. Enable Show versions.
5. Delete all object versions and delete markers.

Ensure no other projects depend on this bucket.

### 4. Remove Deletion Protection

Temporarily remove the following lifecycle configuration from the S3 bucket resource:

```hcl
lifecycle {
  prevent_destroy = true
}
```

### 5. Review Destruction Plan

```bash
terraform plan -destroy
```

Review the resources carefully.

### 6. Destroy Infrastructure

```bash
terraform destroy
```

Enter `yes` to confirm.

### 7. Verify Cleanup

```bash
aws s3 ls

aws ssm get-parameters-by-path \
  --path /mycloud-bootstrap \
  --recursive
```

Verify that the resources managed by this project have been removed.

## Security Best Practices

- Never commit AWS access keys or secret keys.
- Never commit GitHub Personal Access Tokens.
- Never commit Terraform state files or state backups.
- Keep the S3 bucket private.
- Enable S3 versioning and encryption.
- Block all public access.
- Enforce HTTPS-only access.
- Restrict IAM permissions to authorized identities.
- Use unique state keys for different environments.
- Commit `.terraform.lock.hcl` to Git.
- Keep state backups secure.
